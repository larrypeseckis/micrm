## Primary question

Does contribution-class governance require an independent core rule beyond v0.2's alleged-contribution-class structure and ratified investigative-frame authority, or is the remaining content record, challenge, and conformance refinement?

## Answer

Independent core rule required, narrowly. v0.2 supplies the class *structure* (the dimensional profile) and investigative-frame authority supplies *who owns the selection*. Neither supplies the **admissibility gate**: the rule that a proposed class enters the evidence-compatible set only when its material fields are evidence-grounded. That gate is the load-bearing new content, and it is core, not conformance, because attachment, propagation, cut, exclusion, and exit all consume "the admissible class set" and that set is currently unbounded. Everything else in the assignment (the schema, the record fields, the challenge history) is apparatus that hangs off the gate. One core rule, substantial record apparatus, is the correct shape.

## The author-supplied minimum rule, tested

The rule under test (assignment lines 35-48), in two parts:

- **Admissibility gate:** a class enters the evidence-compatible set only where its material fields are grounded by the selected consequence, incident evidence, receiving-interface semantics, authority/provenance predicates, temporal/quantitative/persistence/multiplicity relations, and the selected resolution. "Bare imaginability must not create unresolvedness."
- **Burden rule:** where two or more admissible evidence-compatible definitions produce different results, the finding is unresolved; a hypothetical or strategically proposed class unsupported by incident evidence does not enter the admissible set; where the result is invariant across every admissible class, class-selection uncertainty does not block it.

I tested this against all seven assigned cases. It holds on six and needs one addition on the seventh.

### Case 1: investigator inflation (broaden/serialize until every root stays bound)

Held. The admissibility gate is the defense: each proposed broad class must have its material fields grounded in incident evidence, and a class broadened past what the evidence supports fails grounding and never enters the admissible set. The investigator cannot manufacture unresolvedness because unsupported breadth is inadmissible, not merely unpersuasive. This satisfies success condition 1.

### Case 2: root narrowing (define so narrowly the root lacks one dimension, appears excluded)

Held, but the mechanism is worth stating precisely because it is asymmetric with case 1. A narrow class proposed by an interested root is admissible only if its narrowness is itself evidence-grounded; a class narrowed to *exclude* a dimension the incident evidence supports fails grounding the same way inflation does. But the sharper defense is already ratified: under investigative-frame authority, the narrowing is a claim-selection act owned by the selector, and the dark surface created by excluding a supported dimension is manufactured and attributed to the root that narrowed. "An interested root's unilateral class definition cannot establish its own exit" (section 105) is the explicit block. Satisfies success condition 2.

### Case 3: several plausible definitions, different exit outcomes

Held, and this is the burden rule's core case. All are admissible, they disagree on outcome, the finding is unresolved, and the fork is retained. Correct: genuine evidence-compatible ambiguity is not resolved by pretending one definition is compelled. Satisfies success condition 3. This is the case the rule is *for*, and it does not collapse to either manipulation direction.

### Case 4: class introduced only after reviewing which definition benefits a party

Held by the record, not the gate, which is the important finding. A post-hoc strategically-timed class can still be genuinely evidence-grounded; timing does not make it inadmissible if the evidence supports it. The defense is not exclusion but disclosure: the "date and ordering relative to evidence review" record field (assignment line 84) makes the strategic timing visible, and investigative-frame authority owns it. This is exactly right and mirrors the cluster 1 result that contemporaneity is evidence about the record, not about admissibility. The gate does not reject case 4; the record exposes it. Good design.

### Case 5: abstractly possible class unsupported by incident evidence

Held. This is the "bare imaginability" clause directly. Inadmissible, does not enter the set, does not create unresolvedness. The single most important line in the rule, because it is what prevents the professor's "loaded weapon" from firing: the loaded weapon requires that imaginable-but-unsupported classes count, and this clause says they do not.

### Case 6: fields individually plausible but incompatible with the actual receiving interface

Held, and this is where the receiving-interface-semantics grounding requirement earns its place in the list. A class whose fields describe a mechanism the actual interface could not receive or act on fails interface-compatibility grounding even if each field is independently plausible. The findings schema's "receiving-interface compatibility: established / excluded / unresolved" is the operative finding. This is the subtlest of the seven and the rule handles it cleanly because interface semantics is a named grounding source, not an afterthought.

### Case 7: class revision that changes candidate-root membership after investigation begins

**Needs one addition.** The rule governs admissibility of a class at a point in time; it does not govern the *effect of revision on already-computed findings*. Section 105 lists "how class revisions affect prior candidate-root, cut, exclusion, and dark-surface findings" as a requirement, and the assignment's record includes "revision history," but the tested minimum rule does not state what happens to a prior exclusion finding when the class revises to re-include a root. The gap: a root excluded under class C1, then class revises to C2 under which it is a candidate, must not retain its C1 exclusion as if still valid, nor silently flip to bound without re-evaluation. Proposed addition, in the rule's own idiom:

> A class revision reopens every prior attachment, propagation, cut, exclusion, and dark-surface finding whose result depended on the revised material fields. Findings not dependent on the revised fields persist. A prior finding may not be carried forward under a revised class without re-establishment. The revision, its authority, and the set of reopened findings are recorded.

Without this, case 7 is a laundering vector: revise the class to shed an inconvenient prior finding while keeping the convenient ones. With it, revision is a scoped-reopening event, not a selective-reset. This is the one place the author's rule is incomplete, and it is incomplete in the direction the assignment itself flagged (section 105 bullet 7), so it reads as an acknowledged TODO rather than a missed case.

## The invariance clause, evaluated separately

The assignment's closing emphasis (line 50): "the model should not block an exit because class wording differs when every admissible formulation produces the same outcome." This is the strongest single element of the proposed rule and deserves its own note. It prevents the burden rule from becoming its own denial-of-service: without it, an investigator could block any exit by proposing trivially-different-but-equivalent class wordings, generating formal "competing definitions" that all reach the same result. The invariance clause defeats that by asking whether the disagreement is *outcome-bearing*. Result-sensitivity ("invariant / outcome-changing / unresolved" in the schema) is the finding that operationalizes it. This clause is what keeps case 3's honest unresolvedness from being weaponized into case-1 inflation by another route. It should be marked, under the 8.2 stance discipline, as a normative commitment: MICRM chooses not to block on non-outcome-bearing class ambiguity.

## Findings schema and record content

The eight-field findings schema (assignment lines 53-77) is admission-quality and maps cleanly onto the seven cases: each case resolves to a specific finding value. The record additions (lines 82-91) are necessary and sufficient, with one note: "residual class-discovery dark surface" (line 91) is the field that handles the unknowable case, an admissible class that might exist but has not been proposed, and it correctly routes to unresolved-blocks rather than to a false "no competing class" finding. That field is what stops the invariance clause from over-claiming invariance across only the *discovered* classes when undiscovered admissible classes might change the result. Good.

## Criterion findings (abbreviated)

**4.5 Scope classification:** admissibility gate, burden rule, and invariance clause are core; the eight-field finding and the record additions are apparatus; the challenge mechanism is conformance. The revision-reopening addition (case 7) is core.

**4.9 Adversarial pressure:** all three success conditions met once the case-7 addition is included. Without it, condition-1-by-revision reopens.

**4.11 Scope-authority ownership:** no scope expansion; investigative-frame authority already ratified owns the selection. No new author ruling required beyond disposition and acceptance of the case-7 addition.
